**Day123 - 生成AIで作るセキュリティツール200**

ShamirSharing CipherLabは、Shamirの秘密分散を方眼・バイト表・落とし穴の模型で手を動かして学ぶ教材です。最初に「(2, n)を可視化する」で1人と2人の違いを見てから、「(k, n)を手で追う」で一般のしきい値法へ進みます。秘密分散共有法は1979年にShamirとBlakleyが独立に提案しました。本ツールは、多項式とラグランジュ補間を使うShamirの方式を扱います。Blakleyの幾何学的な方式は実装していません。

Shamirの`(k,n)`しきい値法では、秘密情報`s`から`n`個のシェアを作り、`n`人に1個ずつ渡します。次の二つが条件です。

① `n`人のうち`k`人がシェアを持ち寄れば、秘密情報`s`を復元できます。

② `k−1`人がシェアを持ち寄っても、`s`を復元できません。さらに、`s`についての情報は一切わかりません。どの秘密候補にも多項式が1本ずつ通ることを、方眼で確かめられます。

「(2, n)を可視化する」と「(k, n)を手で追う」の`s`には架空の数を、「バイトで見る」の短い文には練習用の文を入力してください。実際に使っているパスワード、シードフレーズ、鍵の分割や保管には、この教材を使わないでください。シェアの書式、印刷、QR、保管の方法は扱いません。

## ✨ できること

| 段階 | 操作 | 見えること |
|---|---|---|
| (2, n)を可視化する | 1個のシェアで秘密候補を切り替え、2個目を加える | 1点を通る13本の1次以下の式と、2点を通る1本の式 |
| (k, n)を手で追う | GF(p)で配る・k個で戻す・k−1個の候補を重ねる | ラグランジュ係数と、候補ごとに1本の多項式 |
| バイトで見る | UTF-8の短い文をGF(2⁸)で分け、k個から戻す | バイトごとの多項式、XOR、8回のシフトと還元 |
| 確かめる | 改ざん・x=0・足りない枚数の模型を比べる | 検査なし、CRC-32、秘密中の指紋の違い |

書籍と同じく、`D`をディーラー、`s`を秘密情報、`vᵢ=f(i)`を番号`i`のシェアと呼びます。`(k,n)`は、n個のシェアを作り、そのうち任意のk個以上で`s`を復元する設定です。`p`は計算に使う素数で、`p>max(s,n)`とします。多項式の次数は最大k−1で、k=1は0次、k=2は1次、k=3は2次です。既定の`k=3`では`f(x)=s+a₁x+a₂x² (mod p)`を使い、選んだ3点からラグランジュ補間で`s=f(0)`を求めます。

書籍でいうシェアは値`vᵢ`です。本ツールのボタン`#i (i,vᵢ)`では、`#i`がシェア番号、括弧内が復元に使う「番号と値」の組です。冒頭の`(k,n)`は復元に必要な個数と作る個数で、点の座標とは異なります。たとえば`n=7`ならシェアは7個で、番号は`#1`～`#7`です。

「① 配る」の表の下には、各シェアの値`vᵢ=f(i)`と、復元用データ`(i,vᵢ)=(i,f(i))=(i, 代入した式 mod p)`を示します。`n=7`なら7行を表示し、係数や`p`を変えると式と値も更新されます。

「(k, n)を手で追う」タブの既定例は`p=13, k=3, n=5, f(x)=5+4x+2x²`です。復元用の組は`(1,11), (2,8), (3,9), (4,1), (5,10)`で、{1,2,3}の復元係数は`(3,10,1)`、寄与は`(7,2,9)`、秘密は`5`です。2個だけなら13個の候補が残ります。最高次の係数を0以外に限ると、候補`s=1`が消える様子も見られます。

係数は0も許します。そのため多項式は「次数k−1以下」と書きます。`k=1`を選ぶと全員のシェアが秘密そのものになり、「分けていない（ただのコピー）」ことがわかります。

### (2, n)から始める理由

GF(13)は0〜12の13個の値を使う有限体です。足し算・引き算・掛け算の結果を13で割った余りに戻し、0以外の数で割るときは逆元を掛けます。13が素数なので、0以外の数には必ず逆元があります。導入タブには、計算例、素数を使う理由、整数のまま計算したときの漏れ、GF(2⁸)との違いを順に記しました。

導入タブは`p=13, n=5, s=5, a₁=4`で始まり、`f(x)=5+4x (mod 13)`からシェアを作ります。「分散段階」では、ディーラー`D`が`vᵢ=f(i)`を計算して各管理人へ渡します。折りたたみを開くと、`v₁=f(1)=(5+4×1) mod 13=9`から`v₅=f(5)=(5+4×5) mod 13=12`まで、計算と配布先を確認できます。

「復元段階」では管理人#1のシェアから始めます。シェアそのものは値`vᵢ`です。復元では管理人番号`i`（＝`#i`）とシェアの値`vᵢ`を組にして`(i,vᵢ)`と表します。既定の例の`(1,9)`は、管理人番号1（＝#1）とシェア9のセットです。この1点だけを持つ人には、`s=0`なら`a₁=9`という別の式も成立します。候補`s=0～12`のどれにも式が1本ずつあり、係数を一様に選べば候補の確率は変わりません。管理人#2の`(2,0)`を加えると、式は`f(x)=5+4x (mod 13)`に決まり、`s=f(0)=5`を復元できます。

ディーラーの`s`と`a₁`は折りたたみ内で変更できます。参加者が1個のシェアだけを持つ場面では、これらを知らないものとして考えます。2つの方眼は0始まりで、左下のマスが`(0,0)`、右へ進むと`x`、上へ進むと`y`が増えます。マウスを重ねるとマスや点の座標`(x,y)`が表示されます。方眼は有限体の点を示し、実数の連続した直線としては結びません。

「② 1点と2点で式の決まり方を比べる」では、まず普通の座標平面に`(1,9)`を通る3本の直線を描きます。各直線とy軸の交点は`f(0)`、つまり秘密候補`s`で、図では`0・5・12`と異なります。これは1点だけでは直線が決まらないことを示す図です。

GF(13)でも`f₀(x)=9x`と`f₅(x)=5+4x`は別の式です。どちらも`f(1)=9`ですが、`f₀(0)=0`、`f₅(0)=5`です。候補が複数あるのは1点だけでは式が決まらないためで、13で割った余りによる見かけではありません。秘密候補`s`を選ぶと、`a₁=(y−s)÷x (mod 13)`からその点を通る式を求めます。`s=0`なら`f(x)=9x (mod 13)`で、整数の`x=0,1,2`を代入した値は`0,9,5`です。同じ計算を`x=12`まで行って青い点を打ちます。朱の丸は`x=0`に残る13個の秘密候補です。連続した直線を折り返しているわけではありません。導入タブのGF(13)説明も、このタブの`f(x)=5+4x`と5個のシェアを使います。

## 📖 使い方

1. 「(2, n)を可視化する」で、最初の1個のシェアだけを見て秘密候補を切り替えます。どの候補にも選んだ点を通る1次以下の式があります。2人目を選ぶと式と秘密が1つに決まります。ディーラーの設定は折りたたみに置き、参加者に渡る値と区別します。
2. 「(k, n)を手で追う」で`p, k, n, s, a₁…`を変え、配る表と戻す表を読みます。係数は手で入れるか、暗号学的乱数から選べます。
3. `k−1個を選ぶ`を押し、候補を1本ずつ送るか全部重ねます。朱の「最高次の係数を0以外に限る」を切り替えると、消える候補を確認できます。
4. 方眼の点をドラッグするか、点を選んで同じ列のマスをタップします。点をクリックするとフォーカスが移り、上下矢印でも1マス動かせます。k個のときは`Δs=λᵢ(0)·Δ (mod p)`が表とともに更新されます。k−1個未満では曲線は一意に決まらず、薄い点は現在の多項式の一例です。
5. 実数の曲線では点をドラッグしてy切片を動かします。k−1点ならy切片を動かしても同じ点を通れます。この図で点と切片の関係を見た後、整数のままの計算で余りが漏れることを下の表で確かめ、有限体の方眼と比べてください。
6. 「バイトで見る」でUTF-8の文を32バイト以内で入力します。`2≤k≤n≤8`で分け、シェアをk個選んで戻します。16進は常に表示し、正しいUTF-8だけ文字として示します。制御文字はエスケープします。
7. 「確かめる」で検査の層を切り替えます。3つのカードは固定データ`MEET AT DAWN`の模型で、入力した文は使いません。

画面右上の「?」を開くと、操作手順・活用例・入力と保存の扱いを確認できます。座学と出典もヘルプ内の折りたたみ節にあります。

### 「バイトで見る」で増える処理

本書P652–661はGF(p)の数でShamir方式を説明します。「バイトで見る」は、その考え方をPC上の短い文字列へ広げる教材です。画面にも各段階の説明を置きました。

1. 入力した文をUTF-8へ変換します。日本語などは1文字が複数バイトになるため、上限は文字数ではなく32バイトです。
2. 各バイトを独立した秘密情報`s`として扱い、GF(2⁸)で多項式を作ります。係数は`crypto.getRandomValues`から選びます。同じ番号`i`で計算した値を全バイト分並べたものがシェア`#i`です。表は各値を16進で示します。
3. 異なる番号のシェアをk個選び、各バイト位置で`λᵢ(0)`を掛けた値をXORして復元します。k個未満では復元を止めます。
4. 復元結果をまず16進で表示します。正しいUTF-8なら文としても表示し、制御文字はエスケープします。文字表示だけで復元結果を判断しないためです。

GF(2⁸)では足し算がXORで、掛け算には既約多項式`x⁸+x⁴+x³+x+1`を使います。掛け算の8回の手順と表示専用のlog/exp表は、タブの下部で比べられます。シェアのファイル形式や保管・受け渡しは、この教材の範囲に含めていません。

## 🔬 仕組みと限界

GF(p)では`λᵢ(0) = Πⱼ≠ᵢ xⱼ/(xⱼ−xᵢ)`、`s = Σᵢ λᵢ(0)yᵢ`です。GF(2⁸)でも同じ補間を行いますが、足し引きはXORです。掛け算の既約多項式は`x⁸+x⁴+x³+x+1`で、`0x11B`はコード上の表記です。表示するlog/exp表の生成元`{03}`はSLIP-39の参照実装で使われ、{03}の位数255と{02}の位数51は付属テストでも検算します。

実データの分割・復元には、表引きをしない8回のシフトとマスクによる掛け算を使います。[CVE-2023-25000](https://osv.dev/vulnerability/GO-2023-1709)は表引きのタイミングが問題になった実例です。ただしJavaScriptの実行環境で定数時間は保証できません。教育用のブラウザー実装であり、実運用の秘密分散器ではありません。

CRC-32は書き写しの誤りを見つけられますが、書き換えた人がCRCを再計算すれば通ります。秘密に付けたSHA-256の先頭4バイトは、戻った値の不一致を高い確率で見つけますが、悪いシェアの持ち主を特定しません。改ざん者は元の秘密を知らないため、任意の文を狙って復元させることはできず、ずらす量だけを決められます。この模型で`DAWN→DUSK`を見せられるのは、観客に元の秘密が見えているためです。

座学の出典は画面の各節に一次資料・二次資料を分けて示しました。Shamirの原論文は *Communications of the ACM* 22(11), 612–613 (1979), [DOI:10.1145/359168.359176](https://doi.org/10.1145/359168.359176)です。Blakleyの原論文は *Safeguarding Cryptographic Keys*（1979）で、[本文](https://pages.cs.wisc.edu/~cs812-1/Blakley1979.pdf)を確認しました。ラグランジュ補間は[HAC 12.71](https://cacr.uwaterloo.ca/hac/about/chap12.pdf)と、IPUSIRON『暗号技術のすべて』9.2節（P652–661）をあわせて参照できます。Tompa & Wollの本文は未確認で、書誌の年・号は資料間で1988年1(2)と1989年1(3)に割れています。

## 🎯 ユースケース

このツールならではの使い方：

- 数学の授業：学習者が(1,11)(2,8)を固定し、13本の候補を重ねる。候補が1本も優先されない理由を目で追える。
- 有限体の入門：`f(x)=5+4x+2x²`の整数値`21,35`とGF(13)の値`8,9`を並べる。余りから秘密が漏れる場合と漏れない場合を比較できる。
- 実装レビューの演習：レビュー担当が最高次係数の非ゼロ切り替えで`s=1`の候補が消えるのを見て、係数生成の仕様を点検する。
- 謎解き・CTFの題材：作者が公開値だけの問題を作り、参加者が`λ=(3,10,1)`から秘密`5`を計算する。本物の認証情報は使わない。
- プログラミングの授業：2枚を素の実装へ渡すと`2DB1…`の誤ったバイトが出る例から、しきい値とUTF-8の検査を設計する。

ほかに、『暗号技術のすべて』9.2節（P652–661）の副読、Day070の視覚暗号との比較、[Day118 SHA-256 Byte Inspector](https://github.com/ipusiron/sha256-byte-inspector)で指紋の仕組みの学習、[Day029 OTP Animation](https://github.com/ipusiron/otp-animation)と情報理論的安全性を比べる教材にも使えます。

## 🔒 入力と実装上の注意

- 保存：言語と明暗のみ。入力した文や係数をlocalStorageやURLに置かない。
- 通信：アプリの計算は外部通信を行わず、`connect-src 'none'`のCSPを設定。
- 入力：UTF-8で32バイト、GF(p)の値は0以上p未満。IMEの変換中は再計算しない。
- 復元：本物の補間関数はx=0、重複x、k未満、長さ不一致を拒否。無防備な模型は別ファイルに分離。
- 限界：異なる分割から混ぜたシェアの正しさや、誰が改ざんしたかはこの教材だけでは証明しない。

## 🧪 テスト

Node.js 22以上で`npm test`を実行します。依存パッケージは不要です。GitHub Actionsでもpushとpull requestの両方で実行します。`python test/interface.browser.py`はPython Playwrightがある環境でChromium・Firefoxを使い、`file://`の操作と320/390/1280pxを検査します。

| 範囲 | 主な検査 |
|---|---|
| A GF(2⁸) | 65,536組の掛け算一致、FIPS 197の2例、逆元255個、生成元の位数 |
| B GF(p) | 既定の5シェア、3組のλ、13候補、消える`s=1`、整数値、`λᵢ(0)·Δ`、k=1 |
| C 分割と補間 | 固定乱数の既知共有、10組すべての3-of-5復元、ランダム往復 |
| D 落とし穴 | 改ざん・CRC・指紋、x=0、k不足、固定ベクターの全項目 |
| E 静的・UI | CSP、保存項目、禁止API、日英辞書、SHA-256の原本一致、画面幅と操作 |

期待値は`test/vectors.json`を読み込みます。固定乱数はi番目のバイトが`(37·i+11) mod 256`です。これはテスト専用で、画面の分割には`crypto.getRandomValues`を使います。
